# The `pwf` command line

`pwf` creates, develops, checks, packs and serves PWFabric applications using
only the engine's own packages. Those commands need no account and no network.
`pwf mcp` serves the same work to AI coding tools. `pwf login`, `logout` and
`whoami` sign the CLI in to [PhiWebs](https://phiwebs.com), the platform
PWFabric was built for; they are the only commands that talk to a hosted
service, and nothing else needs them.

Install it from npm (Node 22): `npm install -g @pwfabric/cli`, or run it
once with `npx -p @pwfabric/cli pwf <command>`. `pwf --version` prints the
installed version. The
[quick start](/quickstart#track-c--build-a-pwfabric-app-from-scratch) walks
through the commands in the order you use them.

```text
pwf <command> [options]
pwf help                   lists the commands
pwf <command> --help       prints one command's usage
```

Options take a value as `--flag value` or `--flag=value`; everything after a
lone `--` is positional. Exit codes: `0` success, `1` failure (an invalid
pack, a missing file, a refused write), `2` wrong usage.

| Command | What it does |
|---|---|
| [`create`](#pwf-create) | Create a new app folder standing on a foundation pack |
| [`dev`](#pwf-dev) | Serve the app locally and reload it on every change |
| [`build`](#pwf-build) | Assemble the app into a static pwapp folder |
| [`validate`](#pwf-validate) | Check a pwpack folder and the packs it pins |
| [`pack`](#pwf-pack) | Write the deterministic `.pwpack` archive of a folder |
| [`add`](#pwf-add) | Install a pack (`.pwpack` or folder) into the project and pin it |
| [`run`](#pwf-run) | Serve a built pwapp (folder or `.pwapp`) on a local port |
| [`mcp`](#pwf-mcp) | Serve the pwf tools to an MCP client (Claude Code, Cursor, VS Code, Gemini CLI, …) |
| [`login`](#pwf-login) | Sign in to PhiWebs |
| [`logout`](#pwf-logout) | Sign out of PhiWebs and delete the saved session |
| [`whoami`](#pwf-whoami) | Show the PhiWebs account and workspace pwf is signed in as |

## `pwf create`

```text
pwf create <name> [--dir <path>] [--foundation <folder|.pwpack>] [--force]
```

| Argument / option | Meaning |
|---|---|
| `<name>` | Lower-case letters, digits and hyphens. The app's id is `@pwpack/local/<name>`. |
| `--dir <path>` | Where to write the app. Default `./<name>`. |
| `--foundation <folder\|.pwpack>` | The foundation pack the app stands on. Default: the `PWF_FOUNDATION` environment variable. One of the two is required. |
| `--force` | Write into a folder that is not empty. |

Writes `pwpack.json`, `app/plan.json`, `app/definitions/appearance.json`,
`app/definitions/navigation.json`, `app/surfaces/home.receipt.json`,
`atoms/README.md` and `.gitignore`. The home page is made from the
foundation's own heading, text and button blocks (whichever it has), and the
theme is one of the foundation's themes. The foundation is copied into
`.pwf/packs/<id>@<version>/` and pinned in `pwpack.json` by content hash, so
`dev` and `run` work offline.

```console
$ pwf create my-app --foundation ./foundation-1.0.0.pwpack
Created @pwpack/local/my-app in …/my-app
  foundation @pwpack/foundation@1.0.0 (sha256:88344a31…)
  cached in  .pwf/packs/@pwpack/foundation@1.0.0
  home page  heading, text, button; theme theme-zinc
```

The foundation pack is released as `foundation-<version>.pwpack` on the
[GitHub releases of pwfabric/packs](https://github.com/pwfabric/packs/releases)
(beside `widgets-<version>.pwpack`); `--foundation` (or `PWF_FOUNDATION`)
points at that file or at a foundation folder.

### `pwf create --pack`

```text
pwf create --pack <name> [--dir <path>] [--id <pack id>] [--requires <folder|.pwpack>] [--force]
```

| Argument / option | Meaning |
|---|---|
| `<name>` | Kebab-case: lower-case letters, digits and single hyphens, starting with a letter, 2–50 characters. `pwf create <name> --pack` works too. |
| `--dir <path>` | Where to write the pack. Default `./<name>`. |
| `--id <pack id>` | The pack's id. Default `@pwpack/<name>`. Written `@<scope>/<name>` or `@<scope>/<publisher>/<name>`. |
| `--requires <folder\|.pwpack>` | A pack this one stands on. It is validated, copied into `.pwf/packs/<id>@<version>/`, pinned in `packs[]` by content hash and added to `requires` as `^<major>.0.0`, as [`pwf add`](#pwf-add) does. |
| `--force` | Write into a folder that is not empty. |

Writes an empty pack: `pwpack.json` (version `0.1.0`, format `1.1`,
`engines.pwfabric` the running engine's release up to its next major,
`requires` empty unless `--requires` is given), `README.md` with the next
commands, `atoms/README.md` and `.gitignore`. No block is written: add one
with [`pwf add block`](#pwf-add-block). The folder validates clean with
`pwf validate`.

## `pwf dev`

```text
pwf dev [dir] [--port <n>] [--host <name>] [--local-host | --no-host] [--debug]
```

| Argument / option | Meaning |
|---|---|
| `dir` | The app folder. Default: the current folder. |
| `--port <n>` | Port to listen on, `0`–`65535`. Default `4600`; `0` picks any free port. |
| `--host <name>` | Interface name or address to bind. Default `127.0.0.1`. |
| `--local-host` | Mount the local host for sign-in and data even when the app declares neither. |
| `--no-host` | Do not mount the local host, even when the app declares sign-in or records. |
| `--debug` | Print an engine error with its stack trace. Without it, an engine error is one line. |

**The local host.** When the app declares sign-in or records, `pwf dev`
mounts a development host under `/_host` beside the pages: records live in
memory, seeded from `app/data/`; one development user signs in with any
e-mail and password; nothing survives a restart. It answers the
[data](/self-host/data) and [session](/self-host/session) protocols, so the
whole loop runs on your machine.

The same pieces are a public entry for hosts of your own:
`import { accessOf, RecordStore, rewriteEntitySources, authAddresses } from '@pwfabric/cli/host'`
(see [Data and receipts](/self-host/data#what-your-host-must-provide)).

Builds the app, serves it, watches the folder and rebuilds and reloads the
page on every change. Runs until Ctrl+C. When a build fails, the terminal
lists the errors, each with its code and file (a JSON syntax error is
`JSON_INVALID <file>`, never a stack trace), and the open page reloads into a
"Build failed" page listing the same errors, which it also prints in the
browser console. The next good build reloads it into the app. If the port is
taken, it says so; pass another `--port` or `--port 0`.

```console
$ pwf dev
built in 1772 ms — 1 page, 3 block types, 56/57 atoms compiled (56 from cache; 1 skipped: RestConnector (connector declared as data, no code to compile))
watching …/my-app (file events)
pwf dev: serving …/my-app at http://127.0.0.1:4600/
press Ctrl+C to stop
built in 619 ms — 1 page, 3 block types, 56/57 atoms compiled (56 from cache; 1 skipped: RestConnector (connector declared as data, no code to compile))
```

The last line is the rebuild after a saved change. "Skipped" names the atoms
that have nothing to compile and why: here a connector that is a declaration
only.

## `pwf build`

```text
pwf build [dir] [--out <dir>] [--router <hash|path|auto>] [--base <path>]
```

| Argument / option | Meaning |
|---|---|
| `dir` | The app folder. Default: the current folder. |
| `--out <dir>` | Where to write the built app. Default `<dir>/.pwf/out/`. |
| `--router <mode>` | How the built app routes: the `router` it passes to `runApp()`. `hash` (default): `#/<page>` addresses, which work on every static host. `path`: clean `/<page>` addresses; the shell carries `<base href>`, and the host must answer every page path with `index.html`. `auto`: path routing where the browser can, else hash; the shell also carries `<meta name="pw-router" content="path">`. |
| `--base <path>` | With `path` or `auto`: the path the app is served under, written as the shell's `<base href>`. Default `/`; `--base /shop/` for an app served at `/shop/`. |

Assembles the app into a static **pwapp**: `index.html`, the runner and its
assets, one compiled bundle per block type, connector engines, and the app's
JSON under `pwpack/`. Prints every diagnostic; on any error, nothing is
written and the exit code is `1`. It judges the pages as
[`pwf validate`](#pwf-validate) does, with the same codes and words
(`UNKNOWN_BLOCK_TYPE`, `BLOCK_ID_DUPLICATE`, …). Compiled atoms are cached in
`.pwf/build-cache/`.

```console
$ pwf build
built 1 page, 3 block types, 0 engines — 56/57 atoms compiled (0 from cache; 1 skipped: RestConnector (connector declared as data, no code to compile)) in 1914 ms
wrote 25 files to .pwf/out

$ pwf build --router path
built 1 page, 3 block types, 0 engines — 56/57 atoms compiled (56 from cache; 1 skipped: RestConnector (connector declared as data, no code to compile)) in 1713 ms
router: path, base / — the host must answer every page path with index.html
wrote 25 files to .pwf/out
```

A path-routed build runs under [`pwf run`](#pwf-run), which answers every page
path with `index.html`, so a deep link such as `/menu` or `/dish?id=…` opens
its page. On another host, configure that fallback (see
[Routing on a static host](/self-host#routing-on-a-static-host)).

The build also writes the app's **Content Security Policy**, derived from what
the app declares: its data addresses, its connections' engine hosts, its
sign-in addresses, its media and its webfonts. The policy is in `index.html`
as a `<meta>`, in `_headers` (the convention most static hosts read) and in
`publish.json` as `csp.policy`; serve it as a header where you can. Anything
it cannot resolve at build time (a compiled engine, a host templated with
config the connection does not set) is listed in `csp.unresolved` and is not
allowed. What a host must add is in the `hosting-security` document of the
[specification](/specification).

## `pwf validate`

```text
pwf validate [dir] [--json]
```

| Argument / option | Meaning |
|---|---|
| `dir` | The pwpack folder. Default: the current folder. |
| `--json` | Print the raw result (`ok`, `issues`, `identity`, `layout`, `atoms`). |

Runs the pack validator and prints its findings as errors, warnings and notes,
with the path each is about. Every `packs[]` pin is looked up in
`.pwf/packs/<id>@<version>/`: a build that is not there is a warning, one
whose content hash differs from the pin is an error. Exit `1` when there is
any error, `0` otherwise.

```console
$ pwf validate
Errors (1):
  UNKNOWN_BLOCK_TYPE app/surfaces/home.receipt.json: page "home" places a block of type "buton", which neither the app nor its pinned packs define
Notes (1):
  DOC_FILE atoms/README.md: atoms/README.md is documentation, not an atom
@pwpack/local/my-app@0.1.0: invalid (1 error, 0 warnings; layout canonical; 0 atoms)
```

Beyond the pack validator's own findings, `validate` (and `pack`) check the
app folder the way the local host reads it:

| Code | Severity | Meaning |
|---|---|---|
| `PIN_NOT_CACHED` | warning | A pinned build is not in `.pwf/packs/`; `pwf add` it. |
| `PIN_HASH_MISMATCH` | error | The cached build's content hash differs from the pin. |
| `PIN_INVALID` | error | A `packs[]` pin cannot name a cache folder. |
| `UNKNOWN_BLOCK_TYPE` | error | A page places a block type that neither the app nor a pinned pack defines; `pwf build` refuses it with the same words. Not judged while a pinned pack is not cached. |
| `BLOCK_ID_DUPLICATE` | error | Two blocks of one page, nested ones included, have the same `id` (an id is unique within its page); the message names both paths. `pwf build` refuses it too. |
| `SEED_INVALID` | error | An `app/data/<typeId>.json(l)` file the local host would reject. |
| `ENTITY_INVALID` | error | `app/definitions/entities.json` is not JSON, or an entry has no `typeId` or a field no `name`. |
| `ENTITY_UNDECLARED` | error | A page binds an entity type `entities.json` does not declare. |
| `ACCESS_RULE_MISSING` | error | A model `entities.json` declares is named by no `access` rule in `app/definitions/auth.json` (or there is no `access` block). A host that publishes the app serves such a model's records to nobody; add a rule, e.g. `{ "subject": "public", "model": "Product", "rule": "read" }` for public data. |

## `pwf pack`

```text
pwf pack [dir] [--out <file>]
```

| Argument / option | Meaning |
|---|---|
| `dir` | The pwpack folder. Default: the current folder. |
| `--out <file>` | Where to write. Default `<dir>/<name>-<version>.pwpack`, where `<name>` is the last segment of the pack id. |

Validates first and refuses on errors. The archive never contains `.pwf/`,
`.gitignore` or `atoms/README.md`. The same folder always gives the same
bytes; the printed hash is the content hash that pins use.

```console
$ pwf pack
Packed @pwpack/local/my-app@0.1.0
  file  …/my-app/my-app-0.1.0.pwpack
  size  1405 bytes, 6 files
  hash  sha256:53553856…
```

## `pwf add`

```text
pwf add <path-to.pwpack|dir> [--dir <project>]
```

| Argument / option | Meaning |
|---|---|
| `<path>` | A `.pwpack` (or `.tgz`) archive, or a pwpack folder. |
| `--dir <path>` | The project folder. Default: the current folder. |

Validates the pack, copies it to `.pwf/packs/<id>@<version>/`, pins it in
`pwpack.json` `packs[]` by content hash and adds
`{ id, range: ^<major>.0.0 }` to `requires`. Only local files and folders:
resolving packs from npm or a pack registry is not supported.

### `pwf add block`

```text
pwf add block <category>/<type> [--dir <project>]
```

| Argument / option | Meaning |
|---|---|
| `<category>/<type>` | The block's category and type. Each is kebab-case, 2–50 characters, starting with a letter. The atom id is `<category>.<type>`. |
| `--dir <path>` | The pack or app folder (it has a `pwpack.json`). Default: the current folder. |

Writes `atoms/blocks/<category>/<type>/manifest.json` and `component.tsx`.
The manifest has `kind: "block"`, the id, `name` (the type a receipt
places), the category, `state: "experimental"`, an empty `definition.props`
and a `knowledge` skeleton to fill in before the pack is published. The
component renders from its props and holds no words of its own: the app
writes every word. Declare each prop in `definition.props` and read it in
the component. A type the folder already has, in any category, is refused.

`block` is the subcommand word, so a pack folder named `block` is added as
`pwf add ./block`.

## `pwf run`

```text
pwf run <dir|file.pwapp> [--port <n>] [--host <name>]
```

| Argument / option | Meaning |
|---|---|
| `<dir>` | A built pwapp folder with an `index.html` (see `pwf build`, or an app exported by any other host). |
| `<file.pwapp>` | A packaged pwapp (a gzipped tar, read like a `.pwpack`), served from memory. |
| `--port <n>` | Port to listen on. Default `4700`; `0` picks a free one. |
| `--host <name>` | Interface to bind. Default `127.0.0.1`. |

```console
$ pwf run .pwf/out
Serving .pwf/out at http://127.0.0.1:4700/
Press Ctrl-C to stop.
```

For an app folder, or its `.pwf/out`, the app's records are served read-only
under `/_host` ([the records protocol](/self-host/data#the-endpoint-table)),
and `pwf run` prints a line saying so. A build copied elsewhere, or a
`.pwapp`, has no app folder beside it and so no records: an address under
`/_host` is then a `404` with a JSON error, code `NO_RECORD_HOST`, never
`index.html`. Serve the app folder, or use `pwf dev`.

Page paths without a file extension are answered with `index.html` and a
`<base href="/">`, so
path-routed apps work; a missing asset is a 404. Headers declared in the
folder's `_headers` file (such as the app's Content Security Policy) are sent
with the files they match. Runs until Ctrl+C.

## `pwf mcp`

```text
pwf mcp
```

Runs a local [Model Context Protocol](https://modelcontextprotocol.io) server
on stdin/stdout, so an AI coding tool can create and check PWFabric apps with
the same functions the commands use. It works in any MCP client: everything
the client needs comes from the server itself — its instructions, each tool's
description, and each answer, which ends with the natural next step. It needs
no account and no network.

| Tool | What it does |
|---|---|
| `pwf_create_app` | `pwf create`: a new app folder on a foundation `.pwpack` |
| `pwf_create_pack` | `pwf create --pack`: a new, empty pack folder |
| `pwf_add_pack` | `pwf add`: install a `.pwpack` (or pack folder) and pin it |
| `pwf_add_block` | `pwf add block`: a new block of the folder's own |
| `pwf_describe_project` | Read-only: the folder's pages, pinned packs, and the blocks (with props) and themes they offer |
| `pwf_validate` | `pwf validate`: every finding with its code and path |
| `pwf_build` | `pwf build`: the static pwapp |
| `pwf_pack` | `pwf pack`: the deterministic `.pwpack` |

Every tool takes `projectDir`, an absolute path, and writes only inside it. A
failure comes back as a tool error with its code and how to fix it. No tool
starts a server: preview with `pwf dev` in a terminal. Foundation and other
open packs are on the [packs releases](https://github.com/pwfabric/packs/releases).

Add it to your client. With `pwf` installed globally the command is `pwf`
with the argument `mcp`; without it, use `npx` as below.

**Claude Code**

```sh
claude mcp add pwfabric -- npx -y @pwfabric/cli mcp
```

**Cursor** — `.cursor/mcp.json` in the project (or `~/.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "pwfabric": { "command": "npx", "args": ["-y", "@pwfabric/cli", "mcp"] }
  }
}
```

**VS Code** — `.vscode/mcp.json` in the project:

```json
{
  "servers": {
    "pwfabric": { "type": "stdio", "command": "npx", "args": ["-y", "@pwfabric/cli", "mcp"] }
  }
}
```

**Gemini CLI** — `~/.gemini/settings.json` (or `.gemini/settings.json` in the project):

```json
{
  "mcpServers": {
    "pwfabric": { "command": "npx", "args": ["-y", "@pwfabric/cli", "mcp"] }
  }
}
```

On Windows, a client that does not run commands through a shell needs
`"command": "cmd", "args": ["/c", "npx", "-y", "@pwfabric/cli", "mcp"]`.

The server is also a library entry, `@pwfabric/cli/mcp`
(`createPwfMcpServer`, `serveStdio`, `TOOLS`), loaded only when used, so the
other commands never load the MCP SDK.

## `pwf login`

```text
pwf login [--server <url>] [--no-browser]
```

| Option | Meaning |
|---|---|
| `--server <url>` | The PhiWebs API. Default `https://api.phiwebs.com`, or `PWF_PHIWEBS_URL` when set (local and staging work). |
| `--no-browser` | Print the sign-in address without opening a browser. |

Signs in with OAuth 2.1 (authorization code and PKCE). `pwf` reads the
server's metadata (`/.well-known/oauth-authorization-server`), registers
itself as a client (dynamic client registration) and remembers that client
per server, opens the sign-in page in your browser (the address is printed
too), and receives the answer on `http://127.0.0.1:<port>/callback`. It asks
for `openid`, `email` and `world:read`: who you are and which workspace.

The tokens are saved in your config folder — `%APPDATA%\pwfabric` on
Windows, `$XDG_CONFIG_HOME/pwfabric` or `~/.config/pwfabric` elsewhere — in a
file only you can read, and refreshed when they expire. The server must be
https; plain http is accepted only on `localhost`.

## `pwf logout`

```text
pwf logout [--server <url>]
```

Revokes the session when the server offers revocation, then deletes the saved
tokens. When the server has no revocation endpoint, the grant stays valid
until it expires; end it at once by removing the "PWFabric CLI" connected app
in your PhiWebs account.

## `pwf whoami`

```text
pwf whoami [--server <url>]
```

Asks the server which account and workspace the saved session belongs to.
Prints "Not signed in" and exits `1` when there is no session.

Source: `packages/cli/src/commands/*.ts` (each command's
`usage`), `packages/cli/src/args.ts` (option parsing),
`packages/cli/src/mcp/` (the MCP server), `packages/cli/src/phiwebs/`
(signing in).
